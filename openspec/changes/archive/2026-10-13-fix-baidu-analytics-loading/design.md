# Design

## Context

动机见 `proposal.md` 的 Why。2026-10-11 的生产浏览器检查发现页面有正确标识、无百度脚本，控制台报告 `Cannot set property dataset of #<HTMLElement> which has only a getter`。

`src/lib/analytics.ts` 同时被客户端与 `vite.config.ts` 引用。其结构类型需要兼容不包含 DOM 类型的 `tsconfig.node.json`。当前 `ScriptElementLike.dataset` 被声明为可替换的可选属性，测试里的脚本元素也使用普通可写对象；两者都未表达真实 DOM 的限制。

加载器通过 `requestIdleCallback` 调度，缺失时使用 `setTimeout`；统计首次访问由百度脚本记录，客户端路由和工具事件分别经已有助手上报。原 `add-baidu-analytics` 变更的任务 5.3、5.4 仍待生产和后台验收；其 `specs/analytics/spec.md` 是本次恢复行为的契约依据。

需要预先确定类型与测试替身的选择，以及离线应用更新后的生产验收方式，因此保留本设计文档。此变更已声明 `skip_specs: true`，不新增或修改需求。

## Goals / Non-Goals

**Goals:**

- 让真实浏览器中的脚本属性写入符合 DOM 约束，并用类型检查阻止整体替换 `dataset`。
- 用能重现旧实现报错的回归测试覆盖故障，并分别核对本地产物、生产浏览器与统计后台。

**Non-Goals:**

- 不更换百度统计、增加统计渠道或重写上报机制。
- 不更改 `onReady` 的现有放行语义，不增加加载失败重试或离线上报。
- 不增加测试依赖、浏览器自动化框架、定时任务或新的页面功能。
- 不在此次提案中发布生产版本、访问管理员后台或启动 15 天监控。

## Decisions

### 1. 写入 dataset 的单个字段

将加载器中的整体赋值改为写入现有 `dataset.analytics` 字段，保留脚本去重选择器、异步属性、URL 和插入位置。将结构类型的 `dataset` 定义为只读引用、必备属性，其记录字段仍可写；继续使用结构类型，避免构建配置依赖 DOM 全局类型。

备选方案是 `setAttribute` 写入标记，需要增加结构接口和调整测试替身的方法。当前真实脚本元素始终提供 `dataset`，属性级赋值配合只读类型即可解决已确认故障，改动更集中。

### 2. 测试替身保持真实的属性限制

在 `src/lib/analytics.test.ts` 中用只有 getter 的属性提供稳定的 `dataset` 对象，使整体赋值在严格模式下报错、字段写入正常。避免继续通过可写属性和 `unknown as HTMLScriptElement` 隐藏宿主差异，尽量让替身直接满足已有结构接口。

先加入回归断言并用旧实现确认失败，再实施修复确认通过。回归检查包括不抛异常、正确标记和 URL、仅插入一次，并覆盖空闲调度与计时器回退。已有开发、关闭统计、离线恢复以及路由和工具事件测试继续验证原契约。

备选方案是新增 DOM 模拟库。此次故障只涉及一个属性的可写性，getter 替身可直接重现，不需要新的依赖；真实浏览器检查作为补充验收。

### 3. 浏览器成功与后台接收分别验收

生产构建预览使用真实浏览器，检查统计标识、仅一个带正确标记的脚本、脚本加载、统计加载器无 TypeError，以及客户端工具切换。预览使用生产产物，可能产生测试访问；记录测试时间和路径。

生产发布后，用新浏览器会话或已更新的页面核对实际脚本和上报请求，再由具备权限的管理员确认实时访客、受访页面及至少一次工具完成事件。保持后台单页应用自动统计关闭，避免与前端补报重复。脚本标签存在或队列有命令都不能单独证明后台已收到数据。

### 4. 从后台验收通过开始观察 15 天

记录验收通过时间 T0（Asia/Shanghai）以及测试访问时间；观察区间为 T0 至 T0 加 15 天，不使用提案创建日作为起点。关注自然访问来源、各工具页访问、工具完成事件；先检查接收是否持续有效，再分析零访问或低使用率。

观察属于发布后的跟进，代码修复和本地测试可独立完成。当前没有创建提醒或自动监控；需要后续安排时由用户另行请求。观察期间暂缓三语和平台迁移，避免同时改变语言、地址和统计渠道。

## Risks / Trade-offs

- 本地测试通过但生产仍使用旧脚本 → 核对发布版本及页面实际资源；遵循现有 PWA 更新提示，在当前处理结束后关闭并重新进入页面，保留用户正在处理的文件。
- 脚本被网络、广告拦截或后台配置影响 → 浏览器请求和后台报表分别检查；缺少后台权限时明确记录待验收，不能宣称统计恢复或开始观察期。
- 真实浏览器和预览访问计入生产统计 → 记录测试时间与路径，解释数据时区分测试访问与自然访问，不增加持久化测试用户标识。
- getter 替身只能覆盖部分 DOM 行为 → 上线前仍检查真实浏览器，不用替身结果替代生产接收证据。
- 原变更尚未归档 → 保留其状态；后续仅在真实验收完成后按原流程处理，不在本提案中同步主规范或勾选原任务。

## Migration Plan

1. 增加能够重现旧实现故障的回归测试，实施最小修复，运行项目测试和 lint。
2. 对生产构建进行真实浏览器检查，记录版本、标识、加载结果和测试时间。
3. 使用现有 EdgeOne 发布流程上线；核对新会话或更新后页面实际使用修复版本。
4. 完成生产网络与百度后台验收，记录 T0 和 15 天观察安排。后台检查未完成时保留待验收状态。
5. 如需要暂时停止统计，使用既有 `VITE_ANALYTICS_ID` 空值构建并发布；统计暂停期间不计入有效观察。业务功能按既有方式运行，旧版本回滚会重新引入本次加载故障。
