# Design

## Context

动机与功能范围见 `proposal.md`，用户行为契约见 `specs/id-photo/spec.md`。本变更跨越新图片工具、路由、静态 HTML、导航和构建检查，且需要提前确定裁切坐标与异步结果生命周期，因此需要设计文件。

已核实的项目现状：

- React + TypeScript + Vite 静态多入口应用，路由定义在 `src/lib/tool-navigation.ts`；`vite.config.ts` 显式列出 HTML 入口并使用 PWA 预缓存。
- `ImageProcessor.tsx` 只支持压缩与水印，两者保持原始宽高；压缩可能因结果体积增加返回原图，其取消逻辑保留本次已完成结果，批量下载逐张触发。
- `OfflineToolsApp.tsx` 在图片分组内保持 `ImageProcessor` 和 `A4ImageLayout` 挂载，以 `hidden` 切换可见性；这两个组件拥有各自的导入数组，并不存在跨页面自动文件传递。
- 项目已有 `Button`、`Card`、`Slider`、`ToggleGroup`、`Popconfirm`、sonner 和统一主题。现有测试包括纯函数、React 静态渲染、源码契约和构建产物检查。
- `navigation`、`site-content`、`site-url` 与 `confirmation` 显式枚举既有工具或页面，需要对应 delta。通用交互、视觉和无障碍要求继续适用。

## Goals / Non-Goals

**Goals:**

- 从原图坐标定义裁切，预览与导出共用计算，窗口尺寸变化不改变构图。
- 逐张保存编辑状态和有效结果，以独立页面接入既有图片分组。
- 将处理结果提交与取消明确分开，保证迟到回调、路由切换和结果失效可验证。
- 使用现有浏览器编码能力和公共组件，控制依赖与回归范围。

**Non-Goals:**

- 不重构旧图片处理器的结果缓存、取消行为或状态模型；已发现的差异在本设计中说明，新页面遵循现有通用规格。
- 不合并不同图片工具的文件列表，不建立跨工具处理流水线，不修改在进行中的百度统计变更。
- 不写入图片打印密度元数据，不增加照片打印功能；毫米与 300 PPI 仅作为预设像素尺寸的换算说明。
- 其余功能边界见提案，不引入图像编辑服务、裁切依赖或 WASM 编解码扩展。

## Decisions

### 1. 独立组件与图片分组路由

新增 `src/tools/id-photo/IdPhoto.tsx`，入口 `/id-photo/`，全站显示名「证件照」。图片组顺序为图片压缩、添加水印、证件照、A4 排版。

`OfflineToolsApp` 将新组件纳入图片分组的固定挂载结构，传入当前是否激活。组件从激活变为非激活时取消处理任务，但保留自身导入数组、设置和有效旧结果；切换到视频或首页导致卸载时清理全部资源，会话恢复范围明确限定在图片分组内部。

备选方案为给 `ImageProcessor` 增加第三种模式。该组件已有依赖体积的原图回退和部分结果取消策略，与证件照契约不同；独立组件能避免这些分支影响裁切。可参考其导入和下载处理，不通过大范围抽取共享状态扩大改动。

### 2. 预设定义与默认值

预设集中在 `src/lib/id-photo-presets.ts`，存储稳定标识、标签、毫米宽高和输出像素宽高。首批提供：

| 标识 | 名称 | 毫米宽 × 高 | 像素宽 × 高 |
|---|---|---|---|
| one-inch | 一寸 | 25 × 35 | 295 × 413 |
| two-inch | 二寸 | 35 × 49 | 413 × 579 |

像素计算为 `round(mm / 25.4 * 300)`；像素矩形是裁切与导出的唯一尺寸依据，避免毫米比例和取整像素比例出现两个版本。预设参考[教师资格认定的一寸要求](https://njit.edu.cn/info/1043/18690.htm)和[湖南省公安厅招聘的二寸要求](https://gat.hunan.gov.cn/gat/jwgk/zfxxgk/xxgkml/rsxx/202506/t20250612_33707473.html)。这些用途对背景等还有自己的要求，页面只呈现尺寸预设。

默认常用尺寸模式、一寸。自定义模式默认按宽度，以首张成功导入图片的原始宽度初始化；已有目标值不随之后切换所选图片或追加图片自动变化。第一版没有百分比输入、可变 PPI、用途审核配置或自定义固定裁切尺寸。

### 3. 共用原图坐标几何

新增 `src/lib/id-photo-geometry.ts`，将裁切、覆盖、边界限制和自定义等比尺寸计算作为纯函数，与 UI 和 Canvas 解耦。

固定模式中，原图尺寸为 `Iw × Ih`，目标为 `Tw × Th`：

- 覆盖所需最小缩放 `s0 = max(Tw / Iw, Th / Ih)`，允许 `s0 > 1`。
- 用户构图倍率 `z` 相对覆盖值定义，默认 1，第一版滑块范围 1–4；实际缩放 `s = s0 * z`。
- 原图上需要保留的矩形为 `sw = Tw / s`、`sh = Th / s`。
- 每张图片存储归一化裁切中心 `cx`、`cy`，初始均为 0.5。中心受 `[sw/(2*Iw), 1-sw/(2*Iw)]` 与对应高度范围限制。
- 源矩形左上角为 `sx = Iw*cx - sw/2`、`sy = Ih*cy - sh/2`；计算只在最终显示时进行屏幕尺寸换算，不提前取整源矩形。

设裁切框屏幕宽度为 `Fw`，屏幕显示系数 `d = Fw/Tw`，指针拖动量 `dx`、`dy` 转为原图中心变化 `-dx/(d*s*Iw)`、`-dy/(d*s*Ih)` 后重新约束中心。缩放时保留当前源中心并重新约束。窗口变化只重新计算 `d`，不改 `cx`、`cy` 或 `z`。

导出使用 `drawImage` 的源矩形和目标矩形形式，将相同 `sx, sy, sw, sh` 渲染到 `Tw × Th` Canvas。预览直接从同一几何结果生成图片布局与裁切框，框外遮罩只是 UI 层，导出不会复制显示区截图。

备选方案是保存 CSS 平移值或读取预览截图。这两种方案依赖显示尺寸，窗口变化可能改变裁切位置或损失原图分辨率；原图坐标能稳定覆盖这些场景。

自定义模式只接受宽度或高度的正整数像素值。按该边比例计算另一边，四舍五入且至少 1 px；检查目标两边均不超过原图。超出时记录该张不可处理原因，绝不静默放大或改成另一目标。输入为空、负数、小数、非有限值时阻止整个处理入口。所有模式保留已有 6000 万原图像素上限，Canvas 创建或编码失败作为单张错误处理。

### 4. 逐张编辑状态与结果版本

每张资源包含稳定 ID、导入序号、原始 File/Blob URL、已解码图片和原始尺寸；常用尺寸编辑信息包含 `cx`、`cy`、`z` 及修订号。模式、预设和自定义轴与目标为页面级设置，裁切构图为每张图片独立设置。

- 切换图片只改变选择，不重置构图。
- 切换模式保存双方设置，但使旧模式结果暂不可下载；再次处理生成当前模式结果。
- 切换预设将所有图片重置为新比例下的居中覆盖并使旧结果失效；这是避免不同宽高比沿用过期构图的明确默认。
- 单张拖动或缩放只提高该张修订号并使该张旧结果失效；其他图片结果保留。
- 模式、预设、自定义目标改变提高全局设置版本，使受影响结果失效。
- 结果记录图片 ID、模式、设置版本和图片修订号；统计完成数、当前下载与全部下载均来自同一有效结果选择器，不沿用旧处理器的索引方式。

批量处理使用开始时的图片和编辑设置快照，期间禁止编辑与导入、清空、移除。图片分组之间只保留每页自身状态，不传播导入文件或结果。

### 5. 裁切界面与可访问操作

采用图片列表、预览区、设置区结构，窄屏时设置与列表换为垂直排列。`Card`、`Button`、`ToggleGroup`、`Slider`、`Popconfirm` 使用现有组件；新领域组件仅承担图片预览和拖动区域，样式使用现有语义 token，文本尺寸遵守项目下限。

常用尺寸模式使用固定比例的裁切框、框外遮罩和构图倍率滑块，不提供裁切框拖动或自由改变宽高。Pointer Events + pointer capture 支持鼠标与单指触控；只在拖动区域限制浏览器触控行为，不拦截页面滚动区。结束、取消或丢失捕获时释放拖动状态。

裁切区域可以聚焦，方向键按目标输出坐标平移 1 px，Shift + 方向键平移 10 px；聚焦滑块后用键盘调整倍率。提供「重置位置」恢复居中覆盖，图片选中态、模式与预设具有可读语义，缩放显示明确倍率与放大清晰度说明。

自定义模式提供按宽度/高度选择、像素输入和实际宽高显示，预览完整图片，不提供裁切拖动。非法输入保留用户文本并显示字段错误，使用同一操作槽位禁用处理。错误与完成反馈使用 sonner，不新增推动内容位置的提示条。

### 6. 处理与导出生命周期

新增 `src/lib/id-photo-export.ts`，按几何配置生成最终尺寸 Canvas，启用图片平滑并请求高质量缩放。PNG 用透明 Canvas；WebP 保留透明；JPEG 沿用原图格式。PNG 使用浏览器默认无损编码，JPEG/WebP 第一版固定质量 0.92，不增加压缩质量控件或调用 PNG 压缩 Worker。

每张编码后验证 Blob 的实际 MIME 类型与所需格式一致；浏览器不支持编码该格式或返回空值时提示该张失败，不静默输出别的格式。结果体积不影响尺寸选择，不调用压缩功能的「更大则返回原图」逻辑。

输出名使用清理后的原名、输出宽高、稳定导入序号与实际格式扩展名，例如 `portrait_295x413_001.jpg`。单张下载使用 Blob URL，全部下载沿用现有逐张顺序方式；不增加 ZIP 功能，处理完成不自动下载。

处理状态至少包括未导入、可处理、处理中、全部完成和部分完成；基于显式状态和有效结果数决定主操作。借用 `deriveModeState` 的通用部分，并为无有效图片或输入无效情况增加明确禁用条件。

以递增任务标识和取消标志隔离异步编码。本次结果只收集在临时数组中，完整循环结束且任务标识仍有效时统一提交成功结果；部分失败可提交其余成功结果，取消则丢弃整个本次结果集。取消保留任务开始前有效结果；处理中禁止下载，避免导出不稳定的结果集合。

同步 Canvas/浏览器编码可能无法被立即中断，取消立即让任务失效，编码回调返回时检查任务标识且不提交结果，再释放临时 Canvas/引用。每张之间让出浏览器执行机会。隐藏路由、卸载、清空、移除通过相应生命周期清理 Blob URL、任务状态与解码对象；导出 URL 下载完成后释放。

**现有行为与规格的差异：** `ImageProcessor` 和其源码守卫测试明确保留取消后的本次部分结果，而 `interaction-modes` 要求取消不产生本次部分产物。证件照独立遵循后者，不复制旧逻辑，也不在本变更中修复旧页面。

### 7. 站点与验证接入

新增 `/id-photo/` 工具页，并纳入 Vite 多入口。同步工具路由/标签/分组、首页卡片与说明、SEO 内容、工具说明、相关工具、无脚本导航、sitemap、许可页脚和 README。

**入口页形态（本节已按事实更新）：** 不再手写 `id-photo/index.html`。`add-trilingual-i18n` 已把入口页改为**构建期生成**：`scripts/vite-plugin-i18n-entries.ts` 依 `src/lib/i18n/` 的语言与工具数据，为每种语言每个工具写出真实 HTML（`/id-photo/`、`/zh/id-photo/`、`/ja/id-photo/`）。因此本变更只需把 `id-photo` 接入工具路由与语言数据源，三种语言的入口、canonical、hreflang、JSON-LD 与 sitemap 条目会自动生成，**不需要（也不应该）新增手写 HTML**。原文「新增 `id-photo/index.html`」的做法已不适用。

沿用 `src/lib/site.ts` 与现有构建注入，新页面携带独立 canonical、OG、Twitter 和 JSON-LD（三种语言各一份，由同一数据源生成）。PWA HTML 匹配规则已有覆盖；产物检查须证明证件照入口及其引用的本地资源可预缓存，修订号与注入后的文件一致。

**入口与 sitemap 的数量口径已改变**：不再是「静态入口从六项改为七项」——`add-trilingual-i18n` 之后入口数为「工具数 × 语言数」，当前 7 × 3 = **21 个**，sitemap 同样为 21 条且每条带 4 条 `xhtml:link` 互指。因此本变更只需保证接入新工具后**每个语言的入口都齐备且互指闭合**，不应再断言具体总数（硬编码 6/7 的断言在语言数变化时必然失效）。工具列表从五项改为六项。

路由 PV 复用已有 `useRouteAnalytics`；保持开发/离线不加载统计、不采集文件内容或用户输入的既有边界。本次不新增证件照工具使用事件，不修改统计类别枚举。

验证组合：纯函数测试几何、约束和整数取整；行为测试验证原图到输出尺寸和区域、透明通道、结果失效与迟到回调；静态渲染检查控件状态、标签及导航；构建检查验证新入口、URL、sitemap 和预缓存。另做浏览器交互验收：拖动、缩放、窗口变化、图片切换、窄屏/主题、路由期间取消和离线导出。不要只通过源码字符串存在推断实际裁切正确。

## Risks / Trade-offs

- [证件照放大导致清晰度下降] → 固定模式遵循用户允许放大的决定，显示简短说明，输出尺寸仍固定；不声称恢复原图细节。
- [预览坐标与编码坐标偏差] → 共用原图坐标几何，测试不同宽高比、边缘位置、倍率和显示区尺寸；使用不对称色块样图验证实际裁切。
- [取消后编码回调提交旧结果] → 任务标识检查贯穿提交路径，临时结果原子提交，并验证取消、路由变化和卸载情形。
- [大量图片内存压力] → 顺序解码/编码，遵循原图上限，及时释放临时 Canvas 和 URL，不建立覆盖原图放大尺寸的中间 Canvas。
- [浏览器拦截多文件下载] → 沿用项目已有逐张下载方式，保留单张下载入口，必要时提示允许多文件下载；ZIP 为后续独立需求。
- [毫米标签被理解为已设置打印密度] → 明确标注 300 PPI 换算说明与输出像素，首版不承诺图片密度元数据或物理打印尺寸。
- [既有测试写死页面/工具数量] → 有针对性地更新导航、SEO、相关链接、页脚、URL 和构建测试，保留其完整覆盖意图。

## Migration Plan

无数据迁移。按任务清单完成后执行现有测试与 lint，并进行浏览器交互验收；发布仍按项目既有静态资源方式由后续明确请求触发。回退时从工具路由与语言数据源移除 `id-photo`，由生成器自行收敛入口，再回退关联导航与构建条目；**不要手工删除生成的 HTML**（它们是构建产物，且删除逻辑受 `GENERATED_MARKER` 保护）。既有图片处理功能不依赖新组件。
